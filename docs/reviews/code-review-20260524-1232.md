## Findings

### 1-未修复-[中]-报告生成器接到未审核指标表会直接 traceback
- **入口/函数**: `scripts/build_value_line.py::main` -> `build_html()` -> `_render_dual_svg()`
- **文件(行号)**: `scripts/build_value_line.py:228`, `scripts/build_value_line.py:375`, `scripts/build_value_line.py:529`
- **输入场景**: 用户误把 `extract_metrics.py` 生成的候选表传给报告生成器，例如 `python3 scripts/build_value_line.py --metrics data/value_line_metrics.csv --output /tmp/report.html`。这是实际可触发的 CLI 输入，因为 `--metrics` 没有限制文件类型，且错误信息只提示先运行 extract/validate。
- **实际分支**: `get_value()` 现在只返回 `status == reviewed` 的值；候选表中所有核心指标仍是 `candidate`，因此 `np_clean` 和 `cf_clean` 都为空；`_render_dual_svg()` 对空列表调用 `min()`。
- **预期行为**: 报告生成器应在入口处验证核心 reviewed 指标是否足够，若输入不是审核版表，应输出清晰错误并非零退出；或者图表 helper 应能安全处理空数据。
- **实际行为**: 命令直接抛出 `ValueError: min() arg is an empty sequence`，没有说明是因为传入了未审核指标表，也没有指出应运行 strict validation 或补充 reviewed 数据。
- **直接证据**: `build_value_line.py:228-236` 会将所有 non-reviewed 值视为缺失；`build_value_line.py:375` 无条件调用 `_render_dual_svg(years, np_clean, cf_clean, ...)`；`build_value_line.py:529-539` 在空输入下调用 `min()`。本次复现命令返回 traceback，路径停在 `_render_dual_svg()` 的 `min()`。
- **影响**: 用户容易在阶段切换时拿 raw candidate CSV 生成报告，得到 Python traceback 而不是可恢复的诊断。这个问题不污染数据，但会让 CLI 工作流脆弱、难以定位。
- **建议改法和验证点**: 在 `build_html()` 入口检查核心指标中 `reviewed` 覆盖是否满足最低要求，不满足时打印“metrics 文件包含未审核核心指标，请先运行 validate_metrics.py 并处理 candidate/missing”并退出；同时让 `_render_dual_svg()` 在空数据时返回 `暂无数据`。增加一个回归测试：用只有 `candidate` 状态的 CSV 调用 build，期望非零退出且无 traceback。
- **修复风险（低/中/高）**: 低
