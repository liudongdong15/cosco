## Findings

### 1-未修复-[高]-报告生成会消费 candidate/missing 数据，绕过人工审核边界
- **入口/函数**: `scripts/validate_metrics.py::main` -> `scripts/build_value_line.py::build_html`
- **文件(行号)**: `scripts/validate_metrics.py:119`, `scripts/validate_metrics.py:203`, `scripts/build_value_line.py:228`
- **输入场景**: 运行当前管线生成 `data/value_line_metrics_reviewed.csv`，其中非核心指标仍保留 `candidate` 或 `missing` 状态，然后运行 `python3 scripts/build_value_line.py --metrics data/value_line_metrics_reviewed.csv`。
- **实际分支**: 校验阶段只把 high-confidence 核心指标自动置为 `reviewed`，其他候选值保持 `candidate`；`can_generate` 只检查是否存在 `conflict` 和核心指标 `missing`，没有阻止非核心 `candidate` 或 `missing`。报告生成阶段 `get_value()` 只要有 `value` 就返回 float，不检查 `status`。
- **预期行为**: 按技术方案，最终报告只能消费审核通过的数据；candidate 值应被阻止进入报告，或至少在报告层被当作未审核值隔离显示，不参与趋势图/结论。
- **实际行为**: `validate_metrics.py --strict` 对当前 108 条记录返回 0，并打印“可以生成 Value Line 报告”，即使审核版 CSV 仍有 20 条 `candidate` 和 25 条 `missing`。`reports/cosco_value_line.html` 已显示候选分红值，例如 2021/2024/2025 的“待复核”分红金额仍进入分红表。
- **直接证据**: `validate_metrics.py:119-127` 将非核心候选保持为 `candidate`；`validate_metrics.py:203-214` 的生成条件没有检查 `candidate`，也没有检查非核心 `missing`；`build_value_line.py:228-235` 直接读取任何非空数值。当前数据中 `data/value_line_metrics_reviewed.csv:17` 的 2018 分红总额是 `candidate`，证据文本只是分红政策披露段落，但报告表格仍显示 `12.30`。
- **影响**: Value Line 页面会把未复核甚至误抽取的候选数据呈现为报告事实，直接违背“AI 不编数/最终数据需人工或规则审核”的核心约束，用户可能基于错误分红、业务拆分或 CCFI 数据做判断。
- **建议改法和验证点**: 让 `validate_metrics.py --strict` 在任何会进入报告的指标存在 `candidate` 或 `conflict` 时非零退出；或者在 `build_value_line.py` 中只消费 `status == reviewed` 的记录，未审核数据统一显示为缺失/待补。补测试：构造一条非核心 `candidate` 有值的 CSV，断言 strict validation 失败或 HTML 不渲染该值。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### 2-未修复-[高]-分部收入抽取不支持千分位逗号，导致业务收入被截断
- **入口/函数**: `scripts/extract_metrics.py::extract_business_segments`
- **文件(行号)**: `scripts/extract_metrics.py:343`
- **输入场景**: 年报分部收入文本包含千分位逗号，例如“集装箱航运业务收入3,840.36 亿元”或“集装箱航运业务收入2,107.31 亿元”。
- **实际分支**: 分部收入正则使用 `(\d+\.?\d*)`，只匹配不带逗号的连续数字；遇到 `3,840.36` 时跳过 `3,`，从 `840.36` 开始匹配，遇到 `2,107.31` 时匹配 `107.31`。
- **预期行为**: 应完整解析带千分位逗号的金额，并使用统一的数字清洗函数处理 `3,840.36` -> `3840.36`。
- **实际行为**: 当前候选指标已经写入错误值：`data/value_line_metrics_reviewed.csv:63` 的证据文本包含“集装箱航 运业务收入3,840.36 亿元”，但 value 是 `840.36`；`data/value_line_metrics_reviewed.csv:99` 的证据文本包含“集装箱航运 业务收入2,107.31 亿元”，但 value 是 `107.31`。
- **直接证据**: `extract_metrics.py:345-349`、`extract_metrics.py:367-369` 的分部收入捕获组均为 `(\d+\.?\d*)`；当前 CSV 的 value/evidence 不一致证明截断已经发生。
- **影响**: 业务拆分图会显著低估集装箱航运收入，尤其 2022、2025 等高收入年份，报告会错误展示主业规模和周期变化。
- **建议改法和验证点**: 将分部收入、分红等所有金额捕获统一改为支持逗号/空格的 `NUM_RE`，并通过 `parse_chinese_number()` 转换；增加回归测试，输入包含 `3,840.36 亿元`、`2,107.31 亿元` 时应分别得到 `3840.36`、`2107.31`。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### 3-未修复-[中]-报告文案硬编码“高度正相关”，没有计算或审核支撑
- **入口/函数**: `scripts/build_value_line.py::_generate_observations`
- **文件(行号)**: `scripts/build_value_line.py:450`
- **输入场景**: 指标表存在任意 CCFI 值，无论覆盖年份是否完整、是否为 `candidate`、是否与净利润逐年对齐。
- **实际分支**: 只要 `ccfi_vals` 非空，就追加“CCFI 年均值...与净利润高度正相关”的结论。
- **预期行为**: 结论应只基于已审核数据和实际计算结果；如果要描述相关性，应计算相关系数并设置覆盖阈值，或者改成更保守的“可用于对照观察”。
- **实际行为**: 当前 CCFI 只有 2017-2021 年报候选值，2022-2025 缺失，但生成报告仍在头部观察中断言“与净利润高度正相关”。
- **直接证据**: `build_value_line.py:450-452` 没有读取状态、没有与净利润交集校验，也没有相关性计算；当前 `data/value_line_metrics_reviewed.csv:2`、`:14`、`:26`、`:38`、`:50` 的 CCFI 都是 `candidate`。
- **影响**: 报告会产生未经验证的分析判断，超出“事实型 Value Line”的边界，并可能在数据缺失或候选值错误时误导读者。
- **建议改法和验证点**: 只基于 `reviewed` CCFI 与 `reviewed` 净利润的交集年份生成描述；若交集少于阈值或未计算相关系数，则不要使用“高度正相关”等强判断。增加测试覆盖 CCFI 部分缺失和全 candidate 的场景。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
