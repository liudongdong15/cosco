## Findings

### 1-未修复-[中]-周度 CCFI 折线会跨缺失周直接连线，图表暗示了不存在的连续周数据
- **入口/函数**: `build_html()` -> `_build_weekly_ccfi_chart()`
- **文件(行号)**: `scripts/build_value_line.py:1095-1100`
- **输入场景**: 周度 CSV 中某年存在缺失周，例如春节/国庆前后没有截图行。当前正式表中就有这种情况：`2022-W04` 后直接到 `2022-W06`，`2023-W03` 后直接到 `2023-W05`，`2024-W06` 后直接到 `2024-W08`，`2026-W07` 后直接到 `2026-W09`。
- **实际分支**: `_build_weekly_ccfi_chart()` 按年排序后，把该年所有点一次性拼成一个 `polyline points="..."`，不检查相邻点 `week_of_year` 是否连续。
- **预期行为**: “每年每周的变化曲线”应区分“连续周变化”和“缺失周空档”。缺失周不能被普通实线桥接成一段看似连续的周度走势，至少应断线、虚线连接或显式标注缺失周。
- **实际行为**: SVG 为每个年份只输出一条连续 `<polyline class="weekly-ccfi-line"...>`；缺失周被视觉上直接连接。比如 `data/external_sources/ccfi_weekly.csv:7` 是 `2022-W04`，下一行 `data/external_sources/ccfi_weekly.csv:8` 是 `2022-W06`，中间 `W05` 缺失，但页面上仍是一段连续实线。
- **直接证据**: `scripts/build_value_line.py:1095` 直接从全部 rows 构造 points；`scripts/build_value_line.py:1098-1100` 输出单条 polyline。数据 gap 检查显示：2022 有 `(4,6)`、`(39,41)`；2023 有 `(3,5)`、`(39,41)`；2024 有 `(6,8)`、`(17,19)`、`(39,41)`；2025 有 `(4,6)`、`(39,41)`；2026 有 `(7,9)`。
- **影响**: 报告读者可能把缺失周之间的线段理解为真实连续周度变化，尤其在周度趋势用于判断运价拐点时会产生误读。数据表本身没有造数，但图表语义会静默放大数据覆盖度。
- **建议改法和验证点**: 在 `_build_weekly_ccfi_chart()` 中按 `week_of_year` 连续性切分 segments；相邻周差值大于 1 时断开 polyline，并可在 legend 或图下方标注“缺失周已断线”。新增测试：构造 `W04`、`W06` 两点，断言 SVG 产生两段 path/polyline 或包含 gap marker，而不是单条连续 polyline。
- **修复风险（低/中/高）**: 低。只影响 SVG 生成逻辑和测试断言，不改变数据表结构。
- **严重程度（低/中/高/严重）**: 中。

### 2-未修复-[低]-报表数据来源区没有展示周度 CCFI 的具体来源范围和事实表入口
- **入口/函数**: `build_html()` 数据来源侧栏
- **文件(行号)**: `scripts/build_value_line.py:667-668`, `scripts/build_value_line.py:1125-1169`
- **输入场景**: 默认 `weekly_ccfi_path` 存在且加载到 220 条 `reviewed` 周度数据，页面渲染出 “CCFI周均值年内曲线”。
- **实际分支**: `build_html()` 在左栏插入 `weekly_chart_block`，但右栏数据来源仍调用 `_build_compact_sources(metrics)`，只传年度 metrics；该函数只汇总年报文件、年度外部数据分类和状态统计。
- **预期行为**: 页面新增一条由截图人工复核表驱动的周度数据系列后，数据来源区应显示周度 CCFI 的事实表、覆盖日期、reviewed 行数和截图来源目录，和年度 CCFI/行情估值一样可追溯。
- **实际行为**: 侧栏“数据来源”只显示年报文件、年度外部数据和状态统计；周度 CCFI 只在页脚有一句泛化说明 “CCFI 周均值来自 Wind 截图人工复核表”，没有 `data/external_sources/ccfi_weekly.csv`、覆盖期或截图目录。
- **直接证据**: `scripts/build_value_line.py:641` 插入周度图；`scripts/build_value_line.py:667-668` 只调用 `_build_compact_sources(metrics)`；`scripts/build_value_line.py:1125-1169` 的来源汇总只遍历 metrics，没有读取 weekly records 或 path。页脚说明在 `scripts/build_value_line.py:675`，但不是可复核来源索引。
- **影响**: 报告本身的来源追踪不完整。CSV 行里有 `source_image/source_row`，但只看 HTML 的用户无法从“数据来源”区定位这条周线来自哪张表、覆盖哪些日期、是否全部 reviewed。
- **建议改法和验证点**: 将 `weekly_ccfi` 和 `weekly_ccfi_path` 传入 sources builder，追加类似 “CCFI周均值：data/external_sources/ccfi_weekly.csv，2021-12-24 至 2026-05-22，220 条 reviewed，截图目录 data/external_sources/ccfi_weekly_images”。新增 HTML 集成测试断言这些关键来源文本存在。
- **修复风险（低/中/高）**: 低。仅增加来源展示文本和测试，不影响数据计算。
- **严重程度（低/中/高/严重）**: 低。
