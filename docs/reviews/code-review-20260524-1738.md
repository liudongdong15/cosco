## Findings

### [P1] External reviewed metrics have no machine-checkable source URL

`CLAUDE.md` defines the repository contract: all numbers must trace to a PDF page or cited external source, and specifically requires `source_url` for external sources (`CLAUDE.md:31-35`). The CSV schema and validator still have no `source_url` field (`scripts/validate_metrics.py:33-37`), and the new external reviewed rows leave `source_file` and `page` blank while marking values as `high/reviewed`, for example CCFI and akshare-derived rows in `data/value_line_metrics_reviewed.csv:2`, `data/value_line_metrics_reviewed.csv:5`, `data/value_line_metrics_reviewed.csv:10`, and `data/value_line_metrics_reviewed.csv:13`.

What can go wrong: the report now displays external CCFI, dividend, market-cap, PE/PB, and price data as reviewed, but a later reviewer cannot reproduce the exact upstream source or snapshot from the data file. `validate_metrics.py --strict` passes these rows because it only enforces `source_file/page` for `annual_report` rows (`scripts/validate_metrics.py:93-100`) and treats any input row already marked `reviewed` as reviewed (`scripts/validate_metrics.py:119-121`). That weakens the main anti-fabrication control exactly where the data is no longer anchored to annual-report PDFs.

Suggested fix: extend `FIELDS` and both CSVs with `source_url` or a structured `source_ref` column for every `source_type=external` row, populate CCFI/akshare rows with stable URLs or local source snapshots, and make `validate_metrics.py --strict` fail external reviewed rows that lack that field. If the source is computed from weekly/monthly observations, include enough provenance to reproduce the calculation, not just a source name in free text.

### [P2] Report source section still says external data is not filled after using it

The generated report correctly shows CCFI values in the annual table and includes the CCFI legend in the chart, but the visible data-source section still says `CCFI、行情估值、回购数据待补齐并审核后展示。` (`reports/cosco_value_line.html:314`). That contradicts the same page, which now shows `reviewed 180`, CCFI values, PE/PB, market-cap, price data, and a footer saying PE/PB comes from akshare and CCFI from annual reports plus external cross-checks (`reports/cosco_value_line.html:321`).

What can go wrong: the user-facing report undermines its own data status. A reader cannot tell whether CCFI and market data are actually reviewed or still placeholders, which is especially risky now that the page includes those values in the core chart and valuation sections.

Suggested fix: update `_build_compact_sources()` to summarize reviewed external sources by type, for example CCFI/SIMIC or 交通运输部, akshare行情, akshare分红, and only say “待补齐” for genuinely missing external categories such as回购 if still absent.
